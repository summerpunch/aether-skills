# Java 实现细则

本文件是[一、编程规约](rulebook/01-programming.md)的应用指引，补充现代 Java 项目的判断条件。完整条文、等级、说明和正反例在规约正文；以下摘要不能替代逐条核对。

## 命名、结构与 API

- 【强制】类用 `UpperCamelCase`，方法、参数和变量用 `lowerCamelCase`，常量用语义明确的 `UPPER_SNAKE_CASE`；包名小写，避免拼音英语混写、侮辱性词语和随意缩写。数组写作 `T[]`。布尔 POJO 属性不要以 `is` 开头；数据库的 `is_xxx` 字段做显式映射。
- 【强制】覆写方法标 `@Override`；通过类名访问静态成员；不要直接改动已被外部调用的公开签名。废弃接口要说明替代方式；避免使用已废弃的 API。
- 【强制】手册要求对外暴露的 Service/DAO 定义接口，实现类用 `Impl` 后缀。项目若采用直接注入实现类、函数式入口或生成式 Repository，先核实实际契约；严格规约检查应说明偏离，不为普通局部修改随意重构整个依赖图。
- 【强制】重写 `equals` 时同时重写 `hashCode`；自定义对象作 `Set` 元素或 `Map` 键时保证二者语义一致。值比较不要依赖包装整数的 `==` 或对象缓存；用常量侧 `equals` 或 `Objects.equals` 避免空指针。
- 【强制】POJO 与数据库字段类型匹配；注意 `bigint` 到 Java 类型的边界。手册要求 POJO/RPC 的可空字段使用包装类型且 POJO 不设属性默认值。应用到 Java `record`、不可变值对象或非 RPC 数据结构时，先核实序列化和缺省值契约，再决定映射方式，不机械套用 JavaBean 规则。
- 【强制】POJO 提供有用的 `toString`，同时避免输出密码、令牌和个人敏感数据；不能把“便于排错”当成打印全部字段的许可。
- 【推荐】访问范围尽量窄，设计扩展优先组合；只在抽象确有复用或边界意义时新增接口。

## 数值、日期与集合

- 【强制】金额按最小货币单位以整数存储；十进制精确运算用 `BigDecimal` 并明确精度、舍入和溢出。不要用 `new BigDecimal(double)`；数值相等用 `compareTo`，需要比较 scale 时才显式比较。浮点计算不要把 `==` 当业务上的近似相等。
- 【强制】日期格式区分 `yyyy` 与周历年 `YYYY`、月份 `MM` 与分钟 `mm`、24 小时 `HH` 与 12 小时 `hh`。不要写死一年 365 天。新代码优先 `java.time`，在边界明确 `ZoneId`、存储时区和序列化格式。耗时测量用单调时钟 `System.nanoTime()`；业务时间使用 `Clock`/`Instant` 等符合当前代码库的 API。
- 【强制】`Collectors.toMap` 要明确重复 key 的处理，且确认 value 不为 `null`；`subList` 是视图，不能强转为 `ArrayList`，修改原列表可能使视图失效。`Arrays.asList` 不可增删，`Collections.emptyList` 等不可变集合也不可修改。
- 【强制】不要在增强 `for` 遍历中直接对原集合增删；删除可用 `Iterator.remove()` 或在语义清楚时用集合自身的安全 API。比较器必须满足对称、传递及相等一致性。集合转数组使用类型正确的 `toArray(T[])`；JDK 11+ 可按项目惯例采用 `toArray(T[]::new)`。
- 【推荐】已知规模且确有收益时预分配集合容量；遍历 `Map` 的键和值用 `entrySet`/`forEach`。不要把“所有集合都设容量 16”当成性能优化。
- 【强制】可复用的正则表达式预编译；对用户可控文本还要评估灾难性回溯。常量应表达业务含义，避免同一协议值在多处硬编码；不要为明显的循环边界或语言惯用值制造无意义常量。

## 并发与控制流

- 【强制】共享状态要明确线程安全边界；线程池设置有意义名称与可控的线程数、队列、拒绝策略和关闭时机。手册禁止用会造成无界资源风险的 `Executors` 工厂替代显式线程池配置。若项目使用 Java 21 虚拟线程或框架托管执行器，按实际资源边界检查任务并发、外部连接和生命周期，不凭 API 名称判定合规。
- 【强制】自定义 `ThreadLocal` 在线程复用场景用 `try/finally` 清理；`SimpleDateFormat` 不共享为无保护静态对象，优先不可变的 `DateTimeFormatter`。多资源加锁保持统一顺序；`Lock.lock()` 成功后紧接 `try/finally`，`tryLock()` 先判断是否取得锁再执行和释放。
- 【强制】并发写同一记录要防止丢失更新，选择数据库条件更新/版本号、行锁或其他有效同步手段，并验证冲突处理。锁内避免阻塞 RPC。定时任务异常不可悄悄终止整个调度链。
- 【强制】`if/else/for/while/do` 使用花括号；`switch` 分支明确终止、返回或有意贯穿；循环退出条件不要依赖并发计数“恰好相等”。
- 【强制】类/方法的 Javadoc、接口抽象方法说明、枚举值说明按手册和仓库约定维护；注释应解释业务约束和原因，与代码同步。手册还要求类的创建者和日期，已有仓库若用 Git 元数据替代，应在严格合规检查中明确指出该差异，而不要伪造作者信息。
