# 服务质量、安全与测试

本文件是[前后端规约](rulebook/programming/10-api.md)、[异常日志](rulebook/02-errors-logging.md)、[单元测试](rulebook/03-testing.md)、[安全规约](rulebook/04-security.md)与[服务器](rulebook/06-project-structure.md)的应用指引。优先检查用户可见契约、失败路径和数据保护；完整条文与等级以规约正文为准。

## API 与异常

- 【强制】公开 API 明确路径、方法、请求/响应、状态码与错误语义。空列表返回空数组/集合而非 `null`；JSON key 采用 `lowerCamelCase`；前端可能丢失精度的超大整数按契约转字符串。不要为了遵循示例而破坏既有 API 兼容性。
- 【强制】能预检的输入错误不要靠捕获 `NullPointerException` 等异常控制流程；仅捕获能处理的范围，保留异常原因。捕获后需要回滚的事务必须保证真实回滚；不要在 `finally` 中 `return`，资源优先用 try-with-resources。
- 【强制】手册二（二）9 要求在 RPC、二方包和动态生成类的边界捕获 `Throwable`，为兼容性故障如 `NoSuchMethodError` 做隔离。执行时只在确有隔离/降级设计的边界捕获：识别后记录并降级或再抛，不要吞掉 `OutOfMemoryError`、`ThreadDeath` 等无法安全恢复的严重错误。
- 【推荐】可能返回 `null` 的方法说明条件；跨服务错误码、异常类型和重试语义应稳定，避免把技术异常直接返回给用户。

## 日志与可观测性

- 【强制】使用日志门面如 SLF4J；参数化日志，异常记录上下文与堆栈。生产代码不用 `System.out`、`System.err` 或 `printStackTrace()` 处理异常。避免重复记录或在每一层都打印同一异常。
- 【强制】手册要求 debug/trace/info 输出时注意级别开关；当参数计算昂贵时先判断是否启用，普通参数化调用可按日志框架实际行为处理。避免整对象 JSON 序列化只为日志，尤其要防止 getter 副作用和敏感数据泄漏。
- 【强制】按适用的法律与项目策略配置日志留存。手册提及普通日志至少 15 天、特定网络安全记录不少于六个月；不要在代码评审中假定所有环境都有相同合规范围。用户敏感信息展示和日志都需脱敏，关联排错优先用安全的业务 ID/trace ID。

## 安全边界

- 【强制】逐对象校验身份与权限，防止水平越权；对所有外部输入做类型、范围、长度、数量和业务有效性检查。覆盖分页、排序字段、URL、文件上传和可能触发 ReDoS 的正则输入。
- 【强制】SQL 值参数绑定；动态表名、列名和排序字段必须限定允许值，不能把用户输入拼进 SQL。HTML 输出按上下文转义；有 Cookie 会话和跨站提交风险的表单/AJAX 执行 CSRF 防护；外部重定向限定目标域。
- 【强制】发送短信/邮件、下单、支付等资源操作要有与风险相称的防重放、频率限制或幂等处理。上传校验大小、类型及存储/访问策略。密码和密钥用项目批准的密钥管理机制，不以可逆“加密后写配置文件”替代密钥管理。

## 测试与远程调用

- 【强制】单元测试自动化、独立、可重复，用断言验证；核心增量代码要有相关测试且通过。测试放在项目标准测试目录，通常是 `src/test/java`。覆盖正常、边界、错误输入和关键状态变化；测试应验证行为而非实现细节。
- 【推荐】手册的 70% 语句覆盖率和核心模块 100% 语句/分支覆盖率是目标而非普适硬门槛。依据风险与仓库已有质量门槛选择测试，避免无意义覆盖。
- 【强制】远程调用设置生效的超时；结合幂等性决定是否重试，并限制重试次数/总时长。对弱依赖明确降级路径，不让其拖垮核心链路。
