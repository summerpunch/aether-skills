# Google Java 源码风格补充

本文件从 Google Java Style Guide 摘取阿里黄山版未明确规定、且不与其冲突的源码组织规则。它是**补充规约**，不是阿里【强制】条款；评审时用 `GJ-01` 等编号引用，不能标成阿里规约。仅在新文件或任务涉及的代码范围应用，避免为了格式统一改写无关文件。若目标仓库已有明确的格式化或导入规则，先在方案中说明差异，按用户确认的范围处理。

| 编号 | 补充条款 | Google 章节 |
| --- | --- | --- |
| GJ-01 | 普通 Java 源文件以一个顶层类为主体，文件名与该类名大小写一致；`package-info.java`、`module-info.java` 按各自用途处理。不要把无关的多个顶层类塞进一个文件。 | §2.1、§3.4.1 |
| GJ-02 | 源文件按版权声明（如有）、`package`、`import`、顶层类型的顺序组织；存在的部分之间留一个空行。 | §3 |
| GJ-03 | 使用明确的类或静态成员导入，不使用 `*` 通配符导入。 | §3.3.1 |
| GJ-04 | 静态导入和非静态导入各成一组，组间留一个空行；组内按导入名称的 ASCII 顺序排列，不额外插空行。导入语句不折行。 | §3.3.2–3.3.3 |
| GJ-05 | 静态嵌套类使用普通导入，不用 `import static` 导入类本身。 | §3.3.4 |
| GJ-06 | 每条语句单独占一行；字段和局部变量通常一条声明只定义一个变量，`for` 循环头部可例外。 | §4.3、§4.8.2.1 |
| GJ-07 | 局部变量靠近首次使用的位置声明，尽量缩小作用域；声明后及时初始化。 | §4.8.2.2 |
| GJ-08 | 类和成员修饰符遵循 Java 语言规范建议的顺序，例如 `public static final`，不要写成 `final public static`。 | §4.8.7 |
| GJ-09 | 需要 Javadoc 时，开头先用简短的概要说明该类型或成员的用途，再补充约束、参数和异常等信息。 | §7.2 |

## 与阿里规约的边界

阿里黄山版的 4 空格缩进、120 字符行宽和 Javadoc 要求保持原样；本文件不引入 Google 的 2 空格缩进、100 字符行宽或 Javadoc 省略条件。不要直接用 `google-java-format` 重排遵循阿里格式的项目，也不要把整个 Google 指南当成已纳入的规则集。
